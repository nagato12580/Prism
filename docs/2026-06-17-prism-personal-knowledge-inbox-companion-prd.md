# Prism 个人知识治理 AI 助手 PRD

版本：v0.1  
日期：2026-06-17  
形态：Web App  
当前阶段：MVP 需求定义与现有代码对齐

## 1. 背景

用户经常在微信、评论区、文章、视频平台、社交平台中看到值得学习或保存的内容，但这些内容通常被临时转发到微信或收藏夹，长期堆积后会出现三个问题：

- 来不及阅读，信息逐渐积压。
- 想找时找不到，收藏变成“黑洞”。
- 有价值的知识点、观点、资源没有被沉淀成可复用的个人知识。

Prism 当前已有个人知识库、Wiki 抽取、Agentic RAG 问答和聊天会话能力。下一阶段需要在此基础上扩展为“个人信息摄入、治理、沉淀和陪伴”的 AI 助手。

## 2. 产品定位

Prism 不只是问答工具，而是用户的个人知识收件箱、信息整理助理、长期记忆系统和陪伴式聊天入口。

一句话定位：

> 用户把看到的东西随手丢进 Prism，Prism 帮用户判断价值、自动分类、生成待审阅建议，并将内容沉淀到 Wiki、笔记、资源、记忆或稍后看中；当用户聊天时，Prism 能结合这些沉淀理解用户、陪伴用户、辅助学习和决策。

产品关键词：

- 个人知识治理，而不是单纯收藏。
- 先收集、后治理，降低用户当下整理成本。
- AI 负责理解、提炼、关联、建议，用户保留最终确认权。
- 对话是知识复用入口，也是个人认知画像持续校准入口。

## 3. 目标用户

### 3.1 核心用户

- 经常学习技术、产品、AI、商业、个人成长等内容的人。
- 经常从不同平台转发、收藏信息，但缺少整理时间的人。
- 需要长期积累个人知识体系的人。
- 希望 AI 能理解自己长期偏好、项目、学习方向和情绪状态的人。

### 3.2 典型用户画像

- 用户正在构建 Prism 项目，希望将其用于个人数据治理。
- 用户会从微信、文章、视频平台、评论区收集内容。
- 用户希望 AI 不只是搜索资料，还能帮助自己消化资料。
- 用户接受 AI 自动建议，但希望最终沉淀前有审阅控制权。

## 4. 核心问题

Prism 需要解决：

1. **收集问题**：外部平台内容分散，用户缺少统一入口。
2. **筛选问题**：用户不知道哪些内容真正值得保留。
3. **分类问题**：知识点、观点、视频资源、灵感、任务、个人记忆混在一起。
4. **沉淀问题**：有价值内容没有进入可复用的 Wiki、笔记或知识库。
5. **召回问题**：沉淀后无法在聊天或问答中自然使用。
6. **陪伴问题**：用户需要的不只是严肃问答，也需要能理解其状态、目标和偏好的 AI。

## 5. 产品目标

### 5.1 短期目标：MVP

建立 `Inbox → 分类 → 审阅 → 沉淀` 基础闭环。

用户可以：

- 粘贴一段内容或链接到 Inbox。
- Prism 自动给出分类建议。
- 用户在审阅台确认或忽略。
- 确认后内容进入知识库、记事本或轻量记忆。

MVP 的体验目标：

> 用户把任意觉得有价值的内容丢进 Prism 后，Prism 至少能完成一次有效的知识转化：看懂它、判断它的类型、提炼可保存内容、给出沉淀位置，并在用户确认后保存。

### 5.2 中期目标

让沉淀内容进入 Prism 问答系统。

用户可以：

- 问知识库中由 Inbox 沉淀出来的内容。
- 查询自己的笔记和观点。
- 让 Prism 基于长期记忆理解自己的偏好、目标、约束。
- 将知识类内容进一步生成 Wiki 页面。

### 5.3 长期目标

形成个人知识治理与陪伴 AI。

用户可以：

- 多渠道自动采集信息。
- 自动整理每日/每周信息 digest。
- 与 Prism 进行自然陪伴式对话。
- 让 Prism 主动提醒待看内容、未审阅内容、长期目标进展。
- 让 Prism 根据长期记忆和知识库提供个性化建议。

## 6. 当前 MVP 状态

当前已实现第一版原型：

- 新增 `/inbox` 页面。
- 支持手动粘贴内容、标题、来源链接、平台。
- 支持自动分类并生成待审阅卡片。
- 支持用户确认沉淀或忽略。
- 支持沉淀到：
  - `KnowledgeItem`
  - `NotebookNote`
  - `MemoryEntry`
- 支持查看最近笔记和轻量记忆。

当前 MVP 还未实现：

- 网页正文抓取。
- 视频元数据抓取。
- 微信自动导入。
- Wiki 自动生成。
- 笔记/记忆检索工具。
- 主动记忆召回。
- 情绪识别与陪伴模式。

## 7. 用户场景

### 7.1 场景一：收藏一条有启发的评论

用户在评论区看到：

> 学习 AI 最重要的不是追模型，而是建立问题分解能力。

用户粘贴到 Prism Inbox。

Prism 识别：

- 类型：观点
- 分类：AI 学习
- 标签：AI、学习方法、问题分解
- 建议动作：保存为笔记

用户确认后，内容进入记事本。

### 7.2 场景二：保存一篇技术文章

用户粘贴一篇文章链接或正文片段。

Prism 识别：

- 类型：知识点
- 分类：RAG / Agent / 前端工程等
- 建议动作：生成 Wiki 或进入知识库

MVP 阶段先沉淀为 `KnowledgeItem`。

后续版本可触发 Wiki 抽取管线，生成结构化知识页。

### 7.3 场景三：保存一个有趣视频

用户粘贴视频链接。

Prism 识别：

- 类型：资源
- 分类：稍后看 / 产品设计 / AI Agent
- 建议动作：保存为资源笔记

用户确认后进入记事本，后续可扩展为视频元数据抓取和摘要生成。

### 7.4 场景四：记录个人长期偏好

用户说：

> 我希望 Prism 第一版先轻量实现，不要过早引入太重依赖。

Prism 识别：

- 类型：记忆
- 分类：产品偏好
- 建议动作：记住

确认后写入 `MemoryEntry`。

未来对话中 Prism 可以主动召回这条偏好。

### 7.5 场景五：陪伴式聊天

用户说：

> 最近有点焦虑，感觉收藏了很多东西但都没看。

Prism 应该：

- 识别这是陪伴/整理场景，而不是严肃知识问答。
- 召回用户长期记忆：用户经常转发学习资料但容易积压。
- 主动给出轻量行动建议：先从最近 20 条里选 3 条。
- 语气温和，不强制引用知识库。

### 7.6 场景六：保存 GitHub 项目

用户粘贴一个 GitHub 仓库链接。

Prism 应该识别：

- 类型：资源 / 技术项目
- 输出风格：项目资料卡
- 可提炼内容：项目用途、核心能力、技术栈、适用场景、是否值得试用
- 与用户关系：是否与 Prism、Agentic AI、知识库、前端工程等当前主题相关
- 建议动作：保存为资源笔记，后续支持抓取 README 并生成知识卡片

### 7.7 场景七：从截图中保存观点

用户上传聊天记录、书摘、评论区截图。

Prism 应该：

- 通过 OCR 提取文字。
- 判断截图里是观点、清单、代码、图表还是对话。
- 提炼其中可复用观点。
- 保留截图作为原始来源。
- 让用户确认是否保存为观点笔记、知识卡片或个人记忆。

MVP 可以先不做 OCR，但数据模型和页面入口需要为图片输入预留扩展点。

## 8. 功能需求

### 8.1 Inbox 收件箱

#### 8.1.1 手动采集

用户可以输入：

- 标题
- 内容
- 来源链接
- 来源平台

提交后创建原始收件 `RawItem`。

优先级：P0

#### 8.1.2 多来源采集

后续支持：

- 微信转发
- 浏览器插件
- 网页剪藏
- 视频链接
- 截图 OCR
- 文件

建议的来源优先级：

| 来源 | 例子 | MVP 策略 | 后续策略 | 优先级 |
| --- | --- | --- | --- | --- |
| 复制文本 | 评论、观点、长文本、自己的想法 | 直接保存并分类 | 支持选中文字快捷保存 | P0 |
| 普通链接 | 博客、知乎、GitHub、小红书页面 | 先保存链接和用户粘贴内容 | 抓取正文、标题、作者和摘要 | P0/P1 |
| 视频链接 | B 站、YouTube、小红书、抖音 | 先保存链接和用户备注 | 抓取标题、简介、字幕和转写 | P1/P2 |
| 截图 | 评论截图、聊天记录、书摘 | 暂不强制支持 | OCR、图表理解、原图留档 | P1 |
| 文件 | PDF、Markdown、文档 | 复用现有上传能力 | 与 Wiki 抽取管线打通 | P1 |
| 待记事项 | 稍后看、要研究、要尝试 | 保存为 task/note | 支持提醒、队列和回顾 | P0/P1 |

优先级：P2

### 8.2 自动分类

Prism 需要将 RawItem 分类为：

- `knowledge`：知识点
- `opinion`：观点/看法
- `resource`：文章、视频、工具、资源推荐
- `task`：稍后看、待处理
- `memory`：关于用户本人的长期偏好、目标、约束
- `idea`：灵感
- `chat`：闲聊片段

分类输出字段：

- 类型
- 标题
- 摘要
- 建议动作
- 分类目录
- 标签
- 理由
- 置信度

优先级：P0

### 8.3 审阅台

用户可以看到待审阅卡片。

每张卡片展示：

- 类型
- 标题
- 摘要
- 原文片段
- 分类
- 标签
- 分类理由
- 置信度

用户操作：

- 确认沉淀
- 忽略
- 后续支持编辑分类和标签

优先级：P0

### 8.3.1 多样化输出风格

Prism 不应对所有输入套用同一个摘要模板。分类后需要根据内容类型生成不同审阅视图。

| 输出风格 | 适用输入 | 核心字段 | 优先级 |
| --- | --- | --- | --- |
| 快速摘要 | 任何内容 | 主题、一句话摘要、价值判断 | P0 |
| 知识卡片 | 技术文章、教程、长文本 | 概念、原理、可复用知识点、相关主题 | P0 |
| 观点分析 | 评论、回答、帖子 | 核心观点、理由、适用边界、可复用表达 | P1 |
| 资源卡片 | 视频、GitHub、工具、文章链接 | 资源用途、适合何时看、下一步动作 | P0 |
| 行动清单 | 待办、稍后看、计划 | 行动项、优先级、建议时间 | P1 |
| 关联分析 | 与已有知识相关的内容 | 相关主题、相似/补充/冲突关系 | P1 |
| 深度笔记 | 高价值长内容 | 结构化笔记、问题、延伸阅读 | P2 |

MVP 可以先统一使用审阅卡片，但分类结果中需要保留 `kind`、`suggested_action`、`category`、`tags`、`rationale`，为后续输出视图升级留接口。

### 8.4 沉淀

#### 8.4.1 知识沉淀

当内容类型为 `knowledge` 或建议动作为 `make_wiki`：

MVP：

- 写入 `KnowledgeItem`
- `source_type = inbox`
- 保留来源 raw item id

后续：

- 可一键生成 Wiki
- 可自动向量化进入 RAG

优先级：P0

#### 8.4.2 笔记沉淀

当内容类型为 `opinion/resource/task/idea`：

- 写入 `NotebookNote`
- 保留 note_type、category、tags、来源

优先级：P0

#### 8.4.3 记忆沉淀

当内容类型为 `memory`：

- 写入 `MemoryEntry`
- 保留 memory_type、importance、category、tags、来源

优先级：P0

### 8.5 笔记本

用户可以查看零散笔记。

MVP 只展示最近笔记。

后续支持：

- 搜索
- 分类过滤
- 标签过滤
- 编辑
- 删除
- 发散生成
- 转 Wiki

优先级：P1

### 8.6 轻量记忆

用户可以查看 Prism 记住的个人偏好、目标、约束。

MVP 只展示最近记忆。

后续支持：

- 编辑
- 删除
- 主动召回
- 记忆冲突处理
- 长期/短期分层

优先级：P1

### 8.7 问答集成

Prism 问答需要逐步接入 Inbox 沉淀内容。

#### 阶段一

知识类沉淀进入 `KnowledgeItem` 后，可手动向量化并被 RAG 检索。

优先级：P1

#### 阶段二

新增工具：

- `note_search`
- `memory_search`
- `inbox_search`

优先级：P1

#### 阶段三

每轮对话前主动召回：

- 用户长期记忆
- 最近关注主题
- 未审阅 Inbox 摘要
- 相关笔记

优先级：P2

### 8.8 陪伴模式

Prism 需要支持不同对话模式：

- 知识问答模式：证据优先、引用明确。
- 信息治理模式：整理、分类、提取、建议行动。
- 陪伴聊天模式：温和、自然、理解用户状态。

陪伴模式需要：

- 不强制查知识库。
- 不强制引用。
- 可以结合用户长期记忆。
- 可以主动建议轻量行动。
- 避免医疗/心理治疗承诺。

优先级：P2

### 8.9 个人认知画像

个人认知画像用于回答一个核心问题：

> 这段新材料为什么对这个用户有价值？

第一版画像不追求复杂推理，但需要保留基础结构：

- 长期兴趣主题：如个人知识管理、Agentic AI、AI 产品设计、工程化落地。
- 当前项目：如 Prism。
- 用户偏好：如偏好轻量实现、不喜欢泛泛总结、希望输出可执行方案。
- 常见问题：用户持续追问或持续收藏的方向。
- 明确排除项：用户不想关注或暂时不需要的方向。
- 已确认记忆：用户审阅后允许 Prism 记住的偏好、目标、约束。

MVP 策略：

- 通过 `MemoryEntry` 保存显式确认的长期偏好。
- 不默认把所有对话自动写入长期记忆。
- 记忆写入前需要审阅确认，尤其是涉及隐私、情绪、身份、关系、健康、财务等敏感内容。

优先级：P1

### 8.10 Agentic 工作流

Prism 第一版的 Agentic AI 不需要拆成多个拟人 Agent，应先实现稳定、可观察、可回滚的任务流。

MVP 工作流：

```text
Intake 接收内容
  -> Type Detect 判断输入类型
  -> Parse 解析标题、正文、来源、平台
  -> Extract 提炼摘要、知识点、观点、行动项
  -> Personalize 结合用户画像判断价值
  -> Relate 查找已有知识关联
  -> Propose 生成分类和沉淀建议
  -> Confirm 等待用户确认/修改
  -> Save 写入知识库/笔记/记忆/稍后看
```

阶段性实现策略：

- M0/M1：用单一后端工作流完成分类和沉淀。
- M2：引入网页/视频/截图解析工具。
- M3：为对话新增 `note_search`、`memory_search`、`inbox_search` 工具。
- M4：拆分采集、阅读、关联、画像、整理等专门 Agent。

优先级：P1/P2

## 9. 非功能需求

### 9.1 可控性

AI 自动分类只生成建议，不应直接污染正式知识库。用户确认后才沉淀。

### 9.2 可溯源

所有沉淀物必须能追溯到原始 RawItem。

### 9.3 可修正

后续需要支持用户修改分类、标题、摘要、标签和沉淀位置。

### 9.4 渐进式复杂度

MVP 不引入 Neo4j，不新增复杂 worker。先使用 MySQL 和现有知识库结构跑通闭环。

### 9.5 容错

分类优先调用 LLM；LLM 不可用时使用规则兜底。

### 9.6 隐私

个人收件箱和记忆内容默认属于用户私有数据。后续多用户版本必须按 user_id 隔离。

### 9.7 可解释性

AI 分类和沉淀建议必须展示理由，让用户知道为什么保存到某个位置。

### 9.8 可扩展性

输入类型、输出风格、沉淀位置和 Agent 工具需要可扩展。MVP 可以使用简单枚举，但命名需要稳定，避免后续迁移成本过高。

## 10. 数据模型

### 10.1 RawItem

原始采集内容。

关键字段：

- id
- user_id
- title
- content
- source_type
- source_url
- source_platform
- status
- created_at

### 10.2 ReviewItem

AI 分类建议。

关键字段：

- id
- raw_item_id
- kind
- title
- summary
- suggested_action
- category
- tags
- rationale
- confidence
- status
- settled_type
- settled_ref_id

### 10.3 NotebookNote

零散笔记、观点、资源、灵感、稍后看。

关键字段：

- id
- title
- content
- note_type
- category
- tags
- source_raw_item_id
- source_review_id

### 10.4 MemoryEntry

轻量长期记忆。

关键字段：

- id
- title
- content
- memory_type
- category
- tags
- importance
- source_raw_item_id
- source_review_id

### 10.5 后续关系模型

后续需要表达新内容与已有知识之间的关系。MVP 可暂不落库，但 PRD 先定义关系类型：

- `similar_to`：相似观点或相似主题
- `supports`：支持已有观点
- `contradicts`：与已有观点冲突
- `extends`：扩展已有知识
- `mentions`：提及已有概念、项目或人物
- `derived_from`：由某个原始资料沉淀而来

落地策略：

- M1/M2：先用标签、分类和来源引用表达弱关系。
- M3：在检索和对话中动态发现关系。
- M4：如确有需要，再引入图数据库或关系表。

### 12.3 页面结构

第一版 Web App 建议保留以下页面：

- `/inbox`：默认信息入口，负责采集、分类、审阅和沉淀。
- `/knowledge`：已沉淀知识和资源的管理入口。
- `/wiki`：结构化知识抽取和知识点页面。
- `/chat`：对话入口，后续接入知识、笔记、记忆和 Inbox 召回。
- `/profile`：后续个人认知画像管理入口。

产品原则：

- 打开 Web App 后应优先进入可操作工作台，而不是营销首页。
- 首页长期可以考虑设为 Inbox 或 Chat + Inbox 快捷入口。
- 移动端需要优先保证快速粘贴、快速保存、稍后审阅。

## 13. 智能分类策略

### 13.1 LLM 分类 Prompt 目标

判断内容属于什么类型，以及应该如何沉淀。

### 13.2 规则兜底

当 LLM 不可用：

- 包含 URL 或视频平台关键词 → resource
- 包含“我希望/我想/我不想/偏好” → memory
- 包含“待办/提醒/稍后” → task
- 包含“观点/认为/看法/启发” → opinion
- 长文本或包含“技术/知识/教程/原理” → knowledge
- 其他 → idea

## 16. 成功指标

MVP 阶段：

- 用户可以在 30 秒内完成一次采集、分类、审阅、沉淀。
- 分类结果可理解，用户知道为什么这样分类。
- 确认沉淀后能在对应区域看到结果。

中期：

- 用户每周愿意持续向 Inbox 丢内容。
- 用户能从 Prism 找回过去沉淀的观点、资源和知识。
- 知识类沉淀能够进入问答系统。

长期：

- Prism 能主动帮助用户减少信息积压。
- Prism 能在聊天中体现对用户偏好、项目和学习方向的理解。
- 用户把 Prism 当作个人信息治理入口，而不是单一问答页面。
