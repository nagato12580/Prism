# Graph Task 3: Project Outbox Events to Neo4j Idempotently

> 实现 `docs/superpowers/plans/2026-07-22-knowledge-graph-outbox-governance.md` 的 **Task 3**，
> 并补上 Task 2 遗留的「ingestion → GraphFactWriter」接线（用户已确认走**完整 Task 3 / 切换 ingestion**）。
> 当前状态：Task 1（scoped 模型 + outbox 表）✅、Task 2（GraphFactWriter + GraphOutboxService）✅ 已落地，
> 但 ingestion 仍走旧的 `settle_entity_candidates` + `project_item_entities` 直接投影路径，**从未发出过 outbox 事件**。

## 现状关键事实（探索确认）

1. **Task 2 的 writer 已存在但未接线**：`GraphFactWriter.settle()` 写 scoped Entity/Alias/Mention/Relation + append outbox 事件（`entity.upserted`/`mention.upserted`/`relation.upserted`），receipt 已按 `REQUIRED_PROJECTORS=("neo4j","milvus_graph")` 双投创建。但 `engine/app/graph/pipeline.py::persist_source_graph` 仍调旧的 `settle_entity_candidates`，`project_source_graph` 仍调 `project_item_entities` 直接写 Neo4j。
2. **payload 已含 Neo4j 投影所需的全部字段**（`graph_facts._entity_payload/_mention_payload/_relation_payload`：含 entity_id/mention_id/relation_id、canonical_name、aliases、normalized_key、file_uid/chunk_uid、evidence_span≤500、confidence）。无需扩 payload。
3. **scoped 写入已就绪**：`GraphClient` 有 `upsert_scoped_entity/source/alias`、`relate_scoped`、`delete_item_sources_generation`、`delete_item_sources_all_generations`、`set_entity_analysis`、`read_entity_communities`，全部以 `(tenant_id, kb_uid, graph_generation, id)` 为键、`MERGE` 幂等。
4. **outbox receipt 模型已就绪**：`GraphProjectionReceipt(event_id, projector, status[pending/applied/retry/failed], attempt, max_attempts=8, next_attempt_at, lease_owner, lease_expires_at, last_error_code, applied_sequence)` + `GraphProjectionCursor(tenant_id, kb_uid, graph_generation, projector, applied_through_sequence)`。`ix_graph_projection_due(projector, status, next_attempt_at)` 索引已建。
5. **SQLite 兼容**：receipt cursor 的 BigInteger sequence 在 SQLite 用 Integer variant；`with_for_update()` 在 SQLite 是 no-op，`SKIP LOCKED` 仅 MySQL 真实生效（测试中 SQLite 退化为普通锁，不阻塞正确性）。
6. **worker 现状**：`engine/app/jobs/worker.py` 的 `KnowledgeWorkerManager` 跑 ingest/governance 两条队列；无 projector 队列。`run_ingest_job` 调 `ingest_item` → `_run_stage_a_for_item` → `run_graph_ingest_pipeline`。
7. **ingestion 现状的 scope**：`_ingest_chunk_graph` 发出的 env 只有 `source_kind/source_id/item_id/text/user_id`，**没有 tenant_id/kb_uid/file_uid/chunk_uid/graph_generation**。`ingest_item` 持有 `item.tenant_id`/`item.kb_uid`/`file_uid`、可从 `KnowledgeTopic.active_graph_generation` 解析 generation。
8. **现有测试假设直接投影**：`test_pipeline_stage_a.py` monkeypatch `pl._project_and_analyze` / `pl._project_item_entities_to_graph`；`test_graph_ingest_pipeline.py` 断言 `project_source_graph` 被调用；`test_stage_a.py` 的 `project_item_entities_*` 直接验证 FakeGraph 收到 MENTIONED_IN/RELATED_TO。这些需适配新的「writer 发事件 + projector 异步投影」模型，但保留 `project_item_entities` 函数本身（Task 3 Step 5 要求：payload builders 保留供 replay，生产路径不再直接投影）。

## 设计决策

### A. 投影器形态：MySQL 拉取式 worker（不新增 Redis 队列）
Task 3 计划要求 `claim_due` 用 `SELECT ... FOR UPDATE SKIP LOCKED` + 60s lease。receipt 表本身就是工作队列（status=pending/retry + next_attempt_at），不需要 Redis。在 `KnowledgeWorkerManager` 增一条 **neo4j 投影线程**，周期性 `claim_due → apply → mark_applied/record_failure`。Milvus 投影（Task 4）后续加同样一条。

**配置开关**：新增 `GRAPH_PROJECTOR_ENABLED`（默认 1）、`GRAPH_PROJECTOR_INTERVAL_SECONDS`（默认 2）、`GRAPH_PROJECTOR_BATCH_LIMIT`（默认 100）。Neo4j 不可用时 receipt 转 retry，worker 下一轮再拉；不影响 ingestion。

### B. ingestion 接线：env 透传 scope + writer 落地 + 移除直接投影
- `_ingest_chunk_graph` / `_finalize_item_graph` 的 env 增加 `tenant_id/kb_uid/file_uid/chunk_uid/graph_generation`。
- `ingest_item` 在 `_run_stage_a_for_item` 前解析 `graph_generation`（从 `KnowledgeTopic.active_graph_generation`；为空则用稳定占位 `f"legacy:{kb_uid}"`，保证有非空 generation——检索侧 `graph_search` 要求 `scope.graph_generation` 非空）。
- `graph/pipeline.py::persist_source_graph`：document_chunk 路径改用 `GraphFactWriter.settle(GraphFactScope(...))`（替代 `settle_entity_candidates`）。需算 `content_hash`（sha256(chunk_text)）和 `extractor_config_hash`（sha256(model+prompt 版本常量)）。
- `graph/pipeline.py::project_source_graph`：**移除 document_chunk 的 `project_item_entities` 调用**（Step 5）。生产 ingestion 不再直接写 Neo4j；Neo4j 由 outbox projector 异步收敛。`personal_asset_unit` 路径暂保留旧 `project_asset_unit_entities`（非 KB 资产，不在本 Task 范围，Task 6 再处理删除语义）。
- 失败隔离不变：writer/projector 任意失败只记日志/转 retry，不阻断入库。

### C. receipt 状态机与错误分类
- `claim_due(projector, worker_id, limit, lease_seconds=60)`：`FOR UPDATE SKIP LOCKED` 拉取 `status IN ('pending','retry') AND next_attempt_at <= now`，置 `status='processing'`、`lease_owner`、`lease_expires_at`。
- `mark_applied(event_id, projector, sequence)`：`status='applied'`、`applied_at`、`applied_sequence=sequence`；推进 `GraphProjectionCursor.applied_through_sequence`（仅当前 applied_sequence == cursor+1 时 +1，跳过乱序——保证 contiguous）。
- `record_failure(event_id, projector, ProjectionFailure)`：retryable 且 attempt<max → `status='retry'`、`attempt+1`、`next_attempt_at=now+backoff`、`last_error_code`；否则 `status='failed'`。
- `classify_neo4j_error(exc)`：`ConnectionError/ServiceUnavailable/ClientError(超时/429)` → retryable `NEO4J_UNAVAILABLE`；未知 event_type/缺 scope/无效 payload → 终态 `GRAPH_EVENT_UNSUPPORTED`/`GRAPH_PAYLOAD_INVALID`。

### D. Neo4j 投影器事件处理（scoped、幂等）
handler 映射 `entity.upserted/mention.upserted/relation.upserted/mention.removed/relation.removed/entity.removed/analysis.updated`。每个 Cypher 重复 scope `(tenant_id,kb_uid,graph_generation)`：
- `_upsert_entity`：`MERGE (e:ScopedEntity {id,tenant_id,kb_uid,graph_generation}) SET e+= {entity_type,canonical_name,normalized_key,status,confidence,user_id}`。
- `_upsert_mention`：`MERGE` ScopedSource（`id=source_kind:source_id`，带 file_uid/chunk_uid/source_type/item_id/title）+ `MERGE (e)-[:MENTIONED_IN]->(s) SET r+={confidence,evidence_span,extraction_method,mention_id,chunk_uid}`。mention_id 作关系属性保证幂等（同一 mention 重放只一条边）。
- `_upsert_relation`：`MERGE (a:ScopedEntity)-[r:RELATED_TO]->(b:ScopedEntity) SET r+={predicate,confidence,evidence_span,relation_id,chunk_uid}`。
- remove 类：删单条事实边（按 mention_id/relation_id）；`entity.removed` 删 Entity 节点（DETACH DELETE）。
- `analysis.updated`（Task 5 才会真正发出，本 Task 先支持 handler 不报错）。

### E. 测试策略
- **单元（SQLite + FakeGraph/FakeReceipt）**：`test_neo4j_outbox_projector.py` 覆盖重复投递收敛为 1 边、瞬态失败转 retry、未知 event 转终态 failed、cursor contiguous 推进、lease 过期可被重新 claim。
- **真实 Neo4j 集成**：`engine/tests/integration/test_graph_projection_recovery.py`（pytest mark `neo4j`，参照 `test_retrieval_scope_isolation.py` 的 GraphClient 直连模式）：插一条 outbox event + receipt → 跑 projector → 断言 Neo4j 里有 1 节点 1 边；停止 Neo4j（或 mock 失败）→ receipt=retry；重启/重放 → 收敛；删一个 file 的 mention → 只删该 file 边、共享 Entity 保留（Gate E 删除语义，但完整删除在 Task 6，这里只验 projector 的 remove handler）。
- **ingestion 接线回归**：修 `test_pipeline_stage_a.py`（断言改为「mention 带 scoped 字段 + 有 outbox 事件」，不再断言直接投影被调）、`test_graph_ingest_pipeline.py`（断言 `project_source_graph` 对 document_chunk 不再调 `project_item_entities`，改为「emit outbox 事件」）、`test_stage_a.py` 的 `project_item_entities_*` 保留（函数仍在，供 replay/Task 6 用，不删除）。

### F. 不做的事（边界）
- 不实现 Milvus 投影器（Task 4）、不实现 generation barrier/激活（Task 5）、不实现删除共享实体完整规则（Task 6）、不实现 graph API 命令（Task 8）。
- 不改 `unified_search`/`graph_search` 检索语义（Task 7）。
- `personal_asset_unit` 路径保留旧投影（非 KB，本 Task 不管）。
- `analyzer.run_analysis` 仍直接写 Neo4j（Task 5 才改为发 `analysis.updated` 事件）；本 Task 的 `analysis.updated` handler 只是预留。

## 风险与回退
- **ingestion 接线是最大回归面**：若 writer 接线出问题，ingestion 失败隔离会吞异常但图会缺数据。回退 = revert Step 5 的 pipeline 改动（恢复 `settle_entity_candidates` + `project_item_entities`）。
- **projector 线程在 worker 内**：若 projector 异常循环，加 try/except + sleep 兜底，单线程不拖垮 ingest。
- **SQLite SKIP LOCKED 不生效**：单测里 receipt 竞态用单线程顺序验证，不依赖 SKIP LOCKED 真实语义；MySQL 集成测验证真实锁。
